SGBD Arquitetura e Componentes Internos

Um SGBD relacional moderno possui componentes organizados em camadas críticas para garantir consistência e performance de busca:

Query Processor Analisa a sintaxe (parser), resolve referências de tabelas/colunas, otimiza o plano de execução e gera as chamadas de código de baixo nível.
Storage Manager Gerencia a alocação de espaço em disco, estruturas físicas de arquivos e índices. Evita acessos lentos de I/O em disco sempre que possível.
Buffer Manager Mantém em memória RAM páginas do banco de dados trazidas do disco. Implementa políticas de cache (como LRU — Least Recently Used).
Transaction Mgr Garante as propriedades ACID. Controla locks e concorrência (Scheduler) e registra o log de transações (Write-Ahead Logging - WAL) para recuperação de falhas.
ACID Transações & Isolamento Concorrente

A propriedade **I** (Isolamento) do ACID impede que transações concorrentes causem inconsistências mútuas. O padrão ANSI SQL-92 define 4 níveis de isolamento baseado em anomalias toleradas:

Nível de Isolamento Leitura Suja (Dirty Read) Leitura Não Repetível Leitura Fantasma (Phantom)
Read Uncommitted Permite Permite Permite
Read Committed Evita Permite Permite
Repeatable Read Evita Evita Permite
Serializable Evita Evita Evita
Pegadinha Clássica: O PostgreSQL implementa o nível Repeatable Read de forma a evitar leituras fantasmas também. Portanto, na prática PostgreSQL e Oracle diferem do comportamento estrito definido no padrão ANSI.
Cebraspe Ordem de Execução Lógica do SQL

Em provas de concursos de TI, é frequente a apresentação de consultas complexas. Para prever o resultado, lembre-se de que a ordem lógica com que o SGBD executa as cláusulas difere de como escrevemos o código:

Ordem Cronológica de Processamento
  1. FROM — Carrega e cruza as tabelas de dados.
  2. ON / JOIN — Filtra linhas com base nos critérios de união.
  3. WHERE — Filtra as linhas individuais. (Não aceita funções de agregação).
  4. GROUP BY — Agrupa as linhas filtradas em subgrupos.
  5. HAVING — Filtra os grupos resultantes. (Aceita funções de agregação).
  6. SELECT — Projeta e formata as colunas de retorno.
  7. DISTINCT — Elimina linhas duplicadas.
  8. ORDER BY — Ordena os dados finais.
  9. LIMIT / OFFSET — Restringe o tamanho do conjunto de resultados.
Diferença crucial: Não tente utilizar um alias criado no SELECT (ex: SELECT salario * 12 AS salario_anual) dentro da cláusula WHERE ou GROUP BY, pois o SGBD tentará processá-las antes de ler o SELECT, causando erro de sintaxe.
Avançado Window Functions (Funções de Janela)

As funções de janela realizam cálculos em um conjunto de linhas que estão relacionadas com a linha atual, sem agrupá-las em uma única linha de saída:

SELECT nome, dept_id, salario, ROW_NUMBER() OVER (PARTITION BY dept_id ORDER BY salario DESC) AS pos_no_dept, DENSE_RANK() OVER (PARTITION BY dept_id ORDER BY salario DESC) AS ranking_denso FROM funcionario;
ROW_NUMBER() Atribui um número sequencial único a cada linha de forma incremental. Se houver empates de valores, os números continuam sequenciais e aleatórios (ex: 1, 2, 3, 4).
RANK() Atribui rankings contendo lacunas se houver empates. Ex: se duas linhas empatam na 2ª posição, a sequência será (1, 2, 2, 4).
DENSE_RANK() Atribui rankings consecutivos sem lacunas em caso de empates. Ex: se duas linhas empatam na 2ª posição, a sequência será (1, 2, 2, 3).
Performance Estruturas Físicas de Indexação

Índices aumentam a velocidade de consultas ao custo de espaço extra em disco e redução na velocidade de escrita (INSERT, UPDATE, DELETE):

B-Tree Estrutura balanceada em árvore multinível. Excelente para buscas de igualdade (=), buscas por intervalo (BETWEEN, <, >) e ordenações (ORDER BY).
Hash Index Usa uma função de espalhamento (hash). É extremamente rápido para buscas exatas por igualdade (O(1)), mas inútil para intervalos e ordenações.
Bitmap Index Vetores de bits que indicam se uma linha contém determinado valor. Ideal para colunas com **baixa cardinalidade** (poucos valores distintos, ex: Status, Genero) e leituras pesadas (Data Warehouse). Péssimo para atualizações frequentes (locks massivos).
