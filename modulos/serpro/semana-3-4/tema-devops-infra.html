Versionamento Avançado com Git e GitLab Core

Merge vs Rebase

O Merge cria um novo commit unindo os históricos, preservando a linha temporal real da equipe. O Rebase reescreve o histórico, movendo a base da ramificação para o topo da branch de destino, resultando em uma linha temporal linear.

Estratégias de Branching

Utilização de modelos como GitFlow ou Trunk-Based Development para orquestrar o desenvolvimento em paralelo sem gerar conflitos destrutivos no repositório principal.

⚡ Foco de Prova

A banca adora testar comandos de recuperação de código como git cherry-pick (trazer um commit específico) e git revert (criar commit que desfaz uma alteração).

Automação com GitLab CI Automate

Continuous Integration (CI)

Prática de integrar código ao repositório principal várias vezes ao dia. Cada integração dispara uma esteira automatizada de build e execução de testes de unidade para detectar falhas o quanto antes.

Continuous Delivery vs Deployment (CD)

Na Entrega Contínua (Delivery), o artefato é gerado e fica pronto para ir para produção, dependendo de uma aprovação manual. No Implante Contínuo (Deployment), a ida para produção é 100% automatizada caso passe nos estágios anteriores.

Rasteira Clássica Cebraspe: Afirmar que a Integração Contínua elimina a necessidade de revisões de código manuais. Errado! A esteira automatiza testes, mas a análise de arquitetura (Code Review) permanece ativa.

Estratégia de Testes & Qualidade de Software QA

Foco Absoluto: Testes de carga e estresse avaliam o comportamento e a resiliência da infraestrutura perante picos de requisições, sendo classificados estritamente como Testes de Requisitos Não Funcionais (RNF).
Dublês de Teste: Mocks vs Stubs

Stubs: Fornecem respostas estáticas e fixadas para as chamadas feitas durante o teste de unidade, servindo para alimentar a execução.

Mocks: São objetos pré-programados que verificam o comportamento e a interação (se o método foi chamado, quantas vezes e com quais parâmetros corretos).

Ordem de Escopo

1. Teste Unitário (Isolado)
2. Teste de Integração (Módulos)
3. Teste de RNF (Carga/Estresse)

Isolamento e Orquestração de Contêineres Infra

EngineDocker

Tecnologia voltada ao empacotamento da aplicação e de todas as suas dependências em uma imagem imutável, rodando em contêineres isolados que compartilham o kernel do sistema operacional nativo.

OrquestraçãoKubernetes & OpenShift

Ferramentas responsáveis por coordenar múltiplos contêineres espalhados em um cluster de servidores. Gerenciam o balanceamento de carga de rede, escalabilidade automática baseada em consumo de CPU e autorrecuperação (self-healing) de pods caídos.

WSL na Prática

Rodar os contêineres em ambientes locais Linux através do WSL (Windows Subsystem for Linux) simula a produção em nuvem de forma nativa e otimiza o uso do Docker Engine.
