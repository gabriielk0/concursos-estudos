Banco de dados relacional

cai todo concurso Formas normais
Pegadinha: a Cebraspe descreve um cenário e pede em qual forma normal a tabela está. Pratique identificar dependências — não decore definições.
1FNSem grupos repetitivos, sem multivalorados. Cada célula tem um único valor atômico.
2FN1FN + sem dependência parcial. Todo atributo não-chave depende da chave inteira. Com chave simples, 1FN já implica 2FN.
3FN2FN + sem dependência transitiva. Se A→B e B→C, C não pode depender de B quando B não é chave.
FNBCTodo determinante é superchave. Mais restrita que 3FN — elimina anomalias residuais.
Mnemônico: "1=átomo · 2=chave toda · 3=sem escada · FNBC=só superchave decide"
cai todo concurso SQL — o que a Cebraspe testa
A banca apresenta SELECT com JOIN + GROUP BY + HAVING e pede o resultado. Execute mentalmente linha a linha.
SELECT d.nome, COUNT(f.id) AS total FROM departamento d LEFT JOIN funcionario f ON f.dept_id = d.id GROUP BY d.nome HAVING COUNT(f.id) > 2 ORDER BY total DESC;
INNER JOINSó linhas com correspondência nos dois lados.
LEFT JOINTodas as linhas da esquerda; NULL onde não há correspondência à direita.
WHERE vs HAVINGWHERE filtra antes do GROUP BY (linhas). HAVING filtra depois (grupos). Não são intercambiáveis.
SubconsultaCorrelacionada referencia tabela externa e executa uma vez por linha. Mais lenta.
alta incidência Álgebra relacional
Confundir projeção com seleção é o erro mais comum. π = colunas. σ = linhas.
σ seleçãoFiltra linhas. Equivale ao WHERE. Ex: σsalario>5000(Funcionário)
π projeçãoSeleciona colunas. Equivale ao SELECT col. Remove duplicatas automaticamente.
⋈ junçãoCombina tabelas por atributos comuns. Junção natural = NATURAL JOIN.
− diferençaLinhas em R que não estão em S. Relações devem ter mesmo esquema.
∪ uniãoTodas as linhas de R e S (sem duplicatas). Requer compatibilidade.

conceito-chave ACID vs BASE
AtomicidadeTudo ou nada. Falha → rollback completo.
ConsistênciaSai de estado válido e chega em estado válido.
IsolamentoTransações concorrentes não se interferem. Níveis: RU < RC < RR < Serializable.
DurabilidadeApós commit, dado persiste mesmo com falha de hardware.
BASEBasically Available · Soft state · Eventually consistent. Modelo NoSQL — troca consistência imediata por disponibilidade.

alta incidência Estruturas de dados
Pilha = LIFO. Fila = FIFO. A Cebraspe inverte os dois — questão clássica.
ArrayAcesso O(1), inserção/remoção no meio O(n). Memória contígua.
Lista ligadaInserção/remoção O(1) dado o nó, busca O(n). Memória não-contígua.
Pilha — LIFOpush/pop O(1). Usos: chamadas de função, undo, parsing.
Fila — FIFOenqueue/dequeue O(1). Usos: BFS, filas de tarefas.
BST balanceadaBusca/inserção/remoção O(log n). AVL e Red-Black rebalanceiam automaticamente.
Hash tableAcesso médio O(1), pior caso O(n) por colisões.
Heap min/maxExtração do mínimo/máximo O(log n). HeapSort e filas de prioridade.
alta incidência OOP — os 4 pilares
Override = runtime, mesma assinatura, subclasse redefine superclasse. Overload = compile time, mesmo nome, assinaturas diferentes. A Cebraspe troca os dois.
EncapsulamentoOcultar estado interno; expor apenas interface pública. Atributos privados + getters/setters.
HerançaSubclasse reutiliza e estende superclasse. Relação "é um". Java não tem herança múltipla de classes — usa interfaces.
PolimorfismoMesmo método, comportamentos diferentes. Sobrescrita (runtime) vs sobrecarga (compile time).
AbstraçãoModelar apenas o essencial. Classes abstratas e interfaces definem contratos sem implementação concreta.

Raciocínio lógico

mais cobrado Tabela-verdade completa
O condicional p→q só é FALSO quando p=V e q=F. Inclusive F→V e F→F são VERDADEIROS — ponto mais explorado pela banca.
pqp∧qp∨qp→qp↔q
VVVVVV
VFFVF ← único falsoF
FVFVV ← confunde!F
FFFFV ← confunde!V
mais cobrado Equivalências do condicional
p→qEquivale a ~p∨q
Contrapositiva~q→~p — EQUIVALENTE. Inverte E nega os dois lados.
Recíprocaq→p — NÃO equivalente. Só inverte.
Inversa~p→~q — NÃO equivalente. Só nega.
Negação~(p→q) = p∧~q — o único caso falso do condicional.
Mnemônico: "Contrapositiva = INVERTE e NEGA = equivalente. Recíproca = só inverte = não equivalente."
alta incidência Negação de quantificadores
Negar "Todos aprovaram" como "Nenhum aprovou" é o erro mais comum. O correto é "Existe pelo menos um que não aprovou."
¬(∀x P)"Todos P" → "Existe pelo menos um que não P"
¬(∃x P)"Existe P" → "Nenhum é P" (Todo P não é P)
argumentos Formas válidas e falácias
Modus Ponens[p→q, p] ⊢ q — VÁLIDO
Modus Tollens[p→q, ~q] ⊢ ~p — VÁLIDO
Sil. hipotético[p→q, q→r] ⊢ p→r — VÁLIDO
Falácia 1[p→q, q] ⊢ p — INVÁLIDO (afirmação do consequente)
Falácia 2[p→q, ~p] ⊢ ~q — INVÁLIDO (negação da antecedente)
